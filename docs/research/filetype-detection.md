# For which buffers is the filetype not enough to choose the Language Plugin or parser?

Research for issue [#41](https://github.com/a1exk-dev/codestyle.nvim/issues/41) (map: [#1](https://github.com/a1exk-dev/codestyle.nvim/issues/1)). It feeds "How does a user format a real buffer?" ([#37](https://github.com/a1exk-dev/codestyle.nvim/issues/37)) and the ticket that #41 blocks ([#42](https://github.com/a1exk-dev/codestyle.nvim/issues/42)).
Question: for the sixteen v1 languages (ADR-0009), where does a buffer's `filetype` fail to name one Language Plugin and one Tree-sitter parser? A spec declares `filetypes`, an optional `match(buf)` and its Tree-sitter language (ADR-0007).

Date of research: 2026-11-03. Sources: Neovim v0.11.7 (`cd90ec7`) and v0.12.6 (`779c369`, current stable) `runtime/lua/vim/filetype.lua`, `runtime/lua/vim/filetype/detect.lua` and `runtime/lua/vim/treesitter/language.lua`; nvim-treesitter `master` (`cf12346`, frozen, for Neovim 0.10/0.11) and `main` (`0195cd6`, for Neovim 0.12+); tree-sitter-blade, tree-sitter-json and shfmt (`mvdan/sh` `56ea45e`) at the commits below; conform.nvim `016802d`; the Research Corpus. Checks ran with the local `nvim --clean --headless` **v0.12.6** and `vim.filetype.match{ filename, buf }`. No 0.11 binary was run; 0.11.7 facts come from its source, and the differences are listed in "Neovim 0.11.7 vs 0.12.6". Terms follow `GLOSSARY.md`. This note gives facts and no design.

Abbreviations: **FT11/FT12** = `filetype.lua` at v0.11.7/v0.12.6, **DT11/DT12** = `filetype/detect.lua`, **TL12** = `treesitter/language.lua` at v0.12.6, **NTM** = nvim-treesitter `master` `lua/nvim-treesitter/parsers.lua`, **NTN** = nvim-treesitter `main` `lua/nvim-treesitter/parsers.lua`, **NTF** = `main` `plugin/filetypes.lua`, **CAT** = Research Corpus `data/catalog.json` (`languages.<slug>.globs`, which come from PhpStorm's own EditorConfig export, `data/default-scheme.editorconfig` section headers).

## Answer

- **The filetype is not enough in five kinds of buffer.**
  1. **One filetype, several parsers.** The parser depends on the filetype *and* on the user's nvim-treesitter branch: `typescriptreact` needs `tsx`, not `typescript`; `jsonc` gets the `jsonc` parser on `master` but the `json` parser on `main` (`main` has no `jsonc` parser); Markdown needs `markdown` plus `markdown_inline`; `xsd`, `xslt` and `svg` all get `xml`; `sh` gets `bash`, `zsh` gets `zsh` only on `main` (no parser on `master`). So one spec cannot name one Tree-sitter language: the TypeScript, JSON and XML plugins each serve filetypes with different parsers.
  2. **Content changes the filetype away from the v1 language.** Neovim reads the buffer: a `.html` file with Twig/Jinja/Django tags (`{% if`, `{% block`, `{# `) becomes `htmldjango`; with Angular syntax (`@if`, `*ngIf`, `ng-template`) `htmlangular`; with an XHTML doctype `xhtml`. A `.xml` with a DocBook doctype becomes `docbk`, with an XBL namespace `xbl`. A `.ts` file that starts with `<?xml` becomes `xml`. PhpStorm decides by name only (`*.html` is HTML, `*.xml` is XML, `*.ts` is TypeScript) [CAT].
  3. **Content decides whether a PHP extension is PHP.** `.inc` is `php` only when `<?` is in its first 20 lines, else `pascal`, `bitbake`, `pov` or an assembler; `.module` is `php` only when line 1 has `<?php`, else `virata`. PhpStorm assigns both to PHP by name [CAT php]. `.install` is `php` with `<?php` on line 1, else `sh` (bash).
  4. **No filetype at all** for names PhpStorm assigns to a v1 language: `*.hphp` (PHP), `*.es6` (JavaScript), `*.ats` (TypeScript), `*.sht`, `*.shtm` (HTML), `*.har`, `*.jsb2`, `*.jsb3`, `*.postman_collection`, `*.postman_environment`, `.ws-context`, `jest.config` (JSON), `*.ant`, `*.fxml`, `*.jhm`, `*.jnlp`, `*.jrxml`, `*.tld`, `phpunit.xml.dist` (XML). Such a buffer has `filetype=""`, so `filetypes` can never match it; only `match(buf)` could.
  5. **The filetype is right, but the text inside is not what the parser expects.** Every `*.twig` file is `twig`, whether it is `x.html.twig`, `x.css.twig` or `x.js.twig`, and nvim-treesitter always injects `html` into Twig `content`. The Blade grammar changed shape between the two nvim-treesitter pins (below).
- **Compound filetypes** (`yaml.ansible`, `markdown.mdx`, `javascript.glimmer`) come from plugins or users. `vim.treesitter.language.get_lang` uses only the part before the first dot when the whole name is not registered [TL12 L36–46]. conform tries the whole name, then each part from last to first, then `_` [conform `lua/conform/init.lua` L223–243].
- **`get_lang` is not the parser oracle.** Without nvim-treesitter, Neovim registers only `help`/`checkhealth` → `vimdoc` and otherwise returns the filetype itself [TL12 L6–9, L36–46]: `typescriptreact`, `jsonc`, `sh`, `xsd` then name parsers that do not exist. The registrations come from nvim-treesitter, and they differ between `master` and `main` (see "Parsers").
- **Other plugins key on the filetype and leave the rest to the user or the tool.** conform picks formatters by `formatters_by_ft[ft]`, whose value may be a function of `bufnr` [init.lua L223–285]. Its `prettier` formatter chooses a Prettier parser through `options.ft_parsers[ft]` or `options.ext_parsers[ext]`, else lets Prettier infer it from `--stdin-filepath $FILENAME` [`formatters/prettier.lua` L9–21, L31–57]. Its `shfmt` formatter passes `-filename $FILENAME` [`formatters/shfmt.lua`]. nvim-treesitter maps filetypes to parsers with `vim.treesitter.language.register` [NTF L1–69; NTM L4–39, L56–66].
- **Shell dialect lives outside the filetype.** Neovim gives `*.bash`, `.bashrc`, `PKGBUILD`, `*.bats` and `#!/bin/bash` scripts the filetype `sh` and records the dialect in `b:is_bash`, `b:is_sh` or `b:is_kornshell`; there is no `bash` filetype [DT12 L1680–1737]. The filename wins over the shebang: `a.bash` with `#!/bin/zsh` is `sh`, while `a.sh` with `#!/usr/bin/env zsh` is `zsh` (checked). shfmt picks its dialect from the filename extension, else the shebang, else bash, and treats `.sh` as POSIX unless a shebang overrides it; on stdin it needs `--filename` for that and for EditorConfig [shfmt `cmd/shfmt/shfmt.1.scd` L67–84].
- **When nothing matches, the neighbours differ.** conform with no formatter configured for the filetype is silent: it logs at debug level and returns "No formatters available for buffer" to the callback. Only when formatters are configured but none is available does it warn once per filetype per session, `Formatters unavailable for <ft> file`, unless `quiet` or `notify_no_formatters = false` [init.lua L538–556, L9–10; `doc/conform.txt` L165–167]. `vim.lsp.buf.format()` with no capable client always says `[LSP] Format request failed, no matching language servers.` [`runtime/lua/vim/lsp/buf.lua` v0.12.6 L643, v0.11.7 L571].

## Details

### 1. How Neovim decides

- `vim.filetype.match` tries, in order: exact file names, then path patterns with non-negative priority, then the extension, then patterns with negative priority, then the content (shebang and first-line patterns) [FT12 L3204–3309, `M.match`]. A pattern beats an extension, which is why `x.blade.php` is `blade` and not `php`.
- Several extensions call a `detect.*` function that reads the buffer: `html` (first 40 lines), `xml` (100), `inc` (20), `module`/`install` (line 1), `make` (up to 1000 lines, only for the flavour), `sh`/`bash` (line 1) [DT12 L833–863, L2016–2034, L914–968, L1173–1217, L1680–1737]. So the filetype of a new, empty `.html` or `.inc` buffer can change after its first lines are written, but only when detection runs again (`:filetype detect`, `:e`).
- `detect.html` returns, in order of the first matching line: `htmlangular` (`@if|@for|@defer|@switch`, `*ngIf`, `*ngFor`, `ng-template`, `ng-content`), `xhtml` (`DTD XHTML`), `htmldjango` (`{%` with one of 27 Django tag names, or `{# `), `superhtml` (`<extend`, `<super>`), else `html` [DT12 L833–863]. The Django tag list includes `block`, `extends`, `for`, `if`, `include`, `filter`, `with`, `verbatim`, so most Twig templates saved as `.html` match. `{{ x }}` alone does not.
- The shebang table maps `php`, `node`/`js` → `javascript`, `make`, `zsh` [DT12 L2051–2066]; `sh`, `bash`, `dash`, `ksh` go through `detect.sh` [DT12 L1680–1737].
- Users and plugins change all of this with `vim.filetype.add`, `g:filetype_md`, `g:filetype_inc`, `g:bash_is_sh`, `g:make_flavor`, modelines and `:setfiletype`.

### 2. Parsers

- nvim-treesitter `master` is frozen and supports Neovim 0.10 and 0.11; `main` is a full rewrite that requires Neovim 0.12 [NTM-README L33, L69; NTN-README L13, L19]. So in practice Neovim 0.11 users have `master` and 0.12 users have `main`.
- **`master` registrations**: a fixed map (`automake` → `make`, `javascriptreact`/`ecma`/`jsx`/`js` → `javascript`, `typescript.tsx` → `tsx`, `svg`/`xsd`/`xslt` → `xml`, `ts` → `typescript`, …) [NTM L4–39], plus every `list.<parser>` with a `filetype` field (`tsx` → `typescriptreact`, `bash` → `sh`, `angular` → `htmlangular`, …) [NTM L56–66, L144–151, L2446–2455]. It has a separate `jsonc` parser (`gitlab.com/WhyNotHugo/tree-sitter-jsonc`) [NTM L1212–1218] and no `zsh` parser.
- **`main` registrations**: `plugin/filetypes.lua` registers, among others, `bash` ← `sh`, `javascript` ← `javascriptreact`, `json` ← `jsonc`, `make` ← `automake`, `markdown` ← `pandoc`, `tsx` ← `typescriptreact`/`typescript.tsx`, `typescript` ← `ts`, `xml` ← `xsd`/`xslt`/`svg`, `angular` ← `htmlangular` [NTF L1–69]. There is no `jsonc` parser in NTN. NTN adds a `zsh` parser (`georgeharker/tree-sitter-zsh` `7a59340`) [NTN L2338–2343].
- **Parsers that need other parsers on `main`** (`requires`): `php` → `php_only`; `html`, `vue` → `html_tags`; `javascript` → `ecma`, `jsx`; `typescript` → `ecma`; `tsx` → `ecma`, `jsx`, `typescript`; `scss` → `css`; `xml` → `dtd`; `markdown` → `markdown_inline` [NTN].
- **Pinned grammar revisions** (NTM `lockfile.json` / NTN `parsers.lua` `revision`): html `cbb91a0`/`73a3947`; php and php_only `576a56f`/`58d5643`; blade `bcdc4b0`/`b5291d1`; twig `085648e`/`2208d2a`; css `6e327db`/`dda5cfc`; scss `c478c68` (both); javascript `6fbef40`/`58404d8`; typescript and tsx `75b3874` (both); vue `22bdfa6`/`ce8011a`; xml `0d9a809`/`5000ae8`; json `46aa487`/`254c42a`; json5 `ab0ba82`/`248b856`; jsonc `02b0165`/—; yaml `1805917`/`a1c4812`; markdown `4132852`/`41ff24a`; editorconfig `3f2b371`/`v2.0.0`; bash `0c46d79`/`a06c2e4`; make `a4b9187`/`70613f3` (the repo moved from `alemuller/tree-sitter-make` to `tree-sitter-grammars/tree-sitter-make`).
- **Blade**: tree-sitter-blade `bcdc4b0` (2025-02-28, package v0.11.0) is a standalone grammar, and `master`'s query injects its `text` nodes as `html` (combined) and `php_only` nodes as `php_only` [NTM `queries/blade/injections.scm` L1–14]. `b5291d1` (2026-08-31, v0.12.2) bundles tree-sitter-html's grammar and extends it (commit `b2cf6d0` "foundation set up for extending tree-sitter-html"), and `main`'s query starts with `; inherits: html` and injects only `php_only` and parameters [NTN `runtime/queries/blade/injections.scm` L1–8]. The HTML of a Blade file is a separate injected tree on one branch and part of the Blade tree on the other.
- **Bundled with Neovim** (both versions): parsers for C, Lua, Vim, Vimdoc, Query and Markdown (with markdown_inline) [nvim `cmake.deps/deps.txt`]. Markdown is the only v1 language whose parser exists without nvim-treesitter.

### 3. PhpStorm's file types

- CAT globs are the section headers PhpStorm writes in its own EditorConfig export, so they list the patterns registered for each language's file type in PhpStorm 2026.2.3 [`tools/parse_export.py` L3, L60–66; `data/default-scheme.editorconfig`].
- The export has no section for `*.jsx`, `*.tsx`, `*.json5`, `*.xhtml`, `*.svg` or the Makefile, and PhpStorm's hashbang detection of shell scripts is not recorded. Where PhpStorm puts those files, and which Code Style they use, is not in the Research Corpus.
- Twig's template data language (HTML by default in PhpStorm) and per-file overrides are not recorded either. The Corpus records only that Twig and Blade's "Hard wrap at" is the margin of "the HTML parts" [`docs/languages/twig.md` L954; `docs/languages/blade.md` L653].

### 4. Neovim 0.11.7 vs 0.12.6

For the sixteen languages, FT11 and FT12 differ only in:
- `Makefile*` names: 0.11.7 sets `make` directly (`starsetf('make')`) [FT11 L2299]; 0.12.6 runs `detect.make` [FT12 L2607]. `detect.make` sets `b:make_flavor` (gnu/bsd/microsoft) on 0.12.6 and only `b:make_microsoft` on 0.11.7 [DT11 L1024; DT12 L1173].
- YAML: 0.12.6 adds `*.kyaml`, `*.kyml`, `.mambarc`, `.kube/kuberc` and `*.grc` (YAML unless `<?xml`).
- JSONC: 0.12.6 adds `waybar/config`.
- Shebang matching: 0.11.7 matches `\<zsh\>`, `\<bash\>` anywhere in the first line; 0.12.6 requires a `#!` line or an exact name [DT11 L1496; DT12 L1680–1725].
- `detect.html` is the same except word boundaries on `ng-template`/`ng-content` [DT11 L748; DT12 L833].
Blade (`%.blade%.php$`), `[jt]sconfig*.json` → `jsonc`, `.ts`/`<?xml` and `htmldjango` detection exist in both [FT11 L2405, L2471, L1266; DT11 L772].

## Facts that bear on other tickets

For "How does a user format a real buffer?" (#37):
- A buffer can have an empty filetype (unnamed buffer, or names such as `phpunit.xml.dist`, `*.es6`, `*.hphp`). A filetype-keyed lookup finds nothing for it; only a `match(buf)` that reads the name or content can.
- conform's convention for "nothing configured for this filetype" is silence (debug log); "configured but unavailable" is one `WARN` per filetype per session; `quiet` and `notify_no_formatters` turn the warning off. `vim.lsp.buf.format` always notifies. ADR-0008 already uses "one warning per buffer and language, and once per session for a missing plugin" for missing Embedded Language plugins.
- Neovim may name the buffer for a language that is out of v1 (`htmldjango`, `htmlangular`, `xhtml`, `docbk`, `pov`, `virata`) when PhpStorm would treat it as HTML, XML or PHP. Whether a v1 plugin claims such a filetype is a decision for the plugin or #42.
- With conform as the hook (#36), conform's `formatters_by_ft` must list the codestyle formatter under each Neovim filetype (`typescriptreact`, `jsonc`, `xsd`, `htmldjango`, …) or under `*`/`_`; conform checks the whole compound filetype first, then its parts.
- Shell: the Shell Script plugin's shfmt call needs `--filename` (or `-ln`) to get the dialect that Neovim stores only in buffer variables. conform's own `shfmt` formatter, which LazyVim uses for `sh`, already passes `-filename $FILENAME`.

For the Language Plugin contract (ADR-0007) and #42:
- A single "Tree-sitter language" per spec does not cover TypeScript (`typescript`/`tsx`), JSON (`json`/`jsonc`/`json5`, branch-dependent), Markdown (two parsers) or the Blade grammar change. A plugin can parse any buffer with any installed parser (`vim.treesitter.get_parser(buf, lang)`), independent of the filetype and of `get_lang`.
- Without nvim-treesitter's registrations, `get_lang` returns the filetype name itself, so `get_lang('typescriptreact')` is `'typescriptreact'`, which is no parser.
