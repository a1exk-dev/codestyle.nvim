# Do coding agents load a parent folder's AGENTS.md, CLAUDE.md and skills from inside a nested Git repo?

Research for issue [#109](https://github.com/a1exk-dev/codestyle.nvim/issues/109) (map: [#95](https://github.com/a1exk-dev/codestyle.nvim/issues/95)).
Question: in a layout where `home/` is a Git repo and `home/codestyle-php.nvim/` is another Git repo (a gitignored clone, or a submodule of `home/`), does an agent session started in the nested repo see `home/`'s `AGENTS.md`, `CLAUDE.md` and skills, and can it edit `home/` or sibling repos without a prompt? What happens when the session starts in `home/`? What do cloud agents check out?

Date of research: 2026-11-15. Sources: official docs, the source code of Codex CLI and opencode at fixed commits (see "Sources"), and runs of the three local CLIs against a test layout. Terms follow `GLOSSARY.md`: the **Core** is codestyle.nvim, a **Language Plugin** supplies one language. The "home" layout is the one the operator is considering; ADR-0020 (one repo per Language Plugin, shared files synced through the template) is the current decision. This note gives facts and no design.

## Answer

| Question (cwd = nested repo unless stated) | Claude Code 2.1.325 | Codex CLI 0.169.0 | opencode 2.3.0 |
|---|---|---|---|
| Loads `home/CLAUDE.md` | **Yes.** It walks from cwd up to `/` and ignores Git roots [CC1] [E1] | No. It does not read `CLAUDE.md`, unless `project_doc_fallback_filenames` names it, and then only in a folder with no `AGENTS.md` [CX2] | No. V2 reads `AGENTS.md` only [OC1] |
| Loads `home/AGENTS.md` | **Yes**, when no `CLAUDE.md` exists in cwd or any folder above it [CC2] [E2]. In a mixed setup, use `@AGENTS.md` imports. The import from a nested repo to `home/AGENTS.md` is "external": it needs a one-time approval in an interactive session, and `-p` skips it [CC3] [E1] | **No** by default. The walk stops at the nearest `.git` [CX1] [E3]. **Yes** if the user config sets `project_root_markers` to a marker file that only `home/` has [CX1] [E4] | **Yes** when the repos are under `$HOME`: it walks up to `$HOME`. Outside `$HOME` it stops at the nested repo's root [OC1] [OC2] [E5] |
| Loads `home/` skills | **No.** `.claude/skills` is searched "up to the repository root", which is the nested repo [CC4] [E1]. It never reads `.agents/skills` | **No** by default. **Yes** with the same `project_root_markers` change. It reads only `.agents/skills` [CX3] [E4] | **Yes**, `.claude/skills` and `.agents/skills` in every folder up to `/`. The code walks to `/`, but the skills page says "up to the project root" [OC3] [OC4] [E6] |
| Edits `home/` or a sibling without a prompt | **No.** File writes outside the working directory ask, also in `acceptEdits`. `--add-dir ..` or `permissions.additionalDirectories` opens them [CC5] [E7] | **No** in `workspace-write`: only cwd, `/tmp`, `$TMPDIR` and `writable_roots` are writable [CX4] [E8]. Note: from inside the nested repo, its own `.git` is read-only, so `git commit` fails in the sandbox [CX5] [E8] | **Yes.** The default policy allows `external_directory`, so writes to `../sibling` run with no prompt [OC5] [E9] |

| cwd = `home/`: nested repos' skills | On demand for a **submodule** or an untracked repo. **Never** for a **gitignored** clone (undocumented; seen in tests) [CC4] [E12] | Never. Skills come only from cwd up to the root [CX3] | Not loaded: discovery walks only upward from cwd [OC3] |
| Git root detection: submodule vs gitignored clone | Both count as their own repo. Trust and the skill walk stop there [CC7] [E1] | Both: the marker check takes any `.git` entry, folder or file [CX7] [E3] | Both: the nearest `.git`, then `git` discovery of its worktree [OC7] |

| GitHub Copilot cloud agent | On GitHub Actions: "Changes are made only in the specific, single repository context". In a cloud sandbox: "Sessions can span across repositories in one organization" [GH1] | `a1exk-dev` is a personal account, so the sandbox's cross-repo mode probably does not apply (**unverified**). Instructions: `AGENTS.md` anywhere in the repo; `CLAUDE.md` only at the root [GH2]. Skills: `.github/skills`, `.claude/skills`, `.agents/skills` [GH3]. **In short:** only opencode follows a home layout fully. Claude Code reads the home's `CLAUDE.md`, or its `AGENTS.md` when no `CLAUDE.md` exists, but not its skills. Codex reads nothing from the home unless every user sets `project_root_markers` in `~/.codex/config.toml`. A project file cannot set it. No cloud agent documents a layout that puts a home folder above a plugin repo. Only opencode can edit sibling repos without a prompt by default.

## 1. Claude Code

Docs at code.claude.com. The code is not public, so the claims below are from the docs and from runs of v2.1.325.

### Instruction files

- [CC1] "Claude Code loads `CLAUDE.md` and `CLAUDE.local.md` from your current working directory and every directory above it. Run Claude Code in `foo/bar/` and it loads instructions from `foo/bar/CLAUDE.md`, `foo/CLAUDE.md`, …" ([memory](https://code.claude.com/docs/en/memory#how-claude-md-files-load)). The walk has no Git-root stop.
- [CC2] `AGENTS.md` (v2.1.277+): "By default, Claude reads `AGENTS.md` only when you have no `CLAUDE.md` in your working directory or above it." When it does, it loads "every `AGENTS.md` and `.claude/AGENTS.md` in your working directory and the directories above it" ([memory § AGENTS.md](https://code.claude.com/docs/en/memory#agents-md)). The default mode is `claude-md-or-agents-md`. The `claude-md-and-agents-md` mode loads both, but you can set it only in user or managed settings, not in a project file (same page).
- [CC3] "An import in a project-level memory file is external when its path resolves outside your working directory … The first time Claude Code encounters external imports in a project, it shows an approval dialog listing the files. If you decline, the imports stay disabled" ([memory § imports](https://code.claude.com/docs/en/memory#import-additional-files)). An `AGENTS.md` that loads through the setting "Loads only if you already approved external imports for this project, with no prompt" (same page, "Where AGENTS.md differs from CLAUDE.md").
- [CC6] "Claude also discovers `CLAUDE.md` and `CLAUDE.local.md` files in subdirectories under your current working directory. Instead of loading them at launch, Claude Code loads each one once Claude reads, writes, or edits another file in that subdirectory." A subdirectory's `AGENTS.md` loads the same way "when Claude opens a file there with the Read tool and that subdirectory has none of the three `CLAUDE.md` files of its own" ([memory](https://code.claude.com/docs/en/memory#how-claude-md-files-load)).

### Skills

- [CC4] "Claude Code loads project skills from `.claude/skills/` in the directory where you start it and in every parent directory up to the repository root." "Skills in a `.claude/skills/` directory below where you started don't load at startup. They load the first time Claude reads or edits a file in that subdirectory" ([skills](https://code.claude.com/docs/en/skills#discovery-from-parent-and-nested-directories)). The docs do not mention `.agents/skills`. They also do not say that a gitignored folder is skipped. The test in [E12] shows that it is.
- `--add-dir <path>` loads that folder's `.claude/skills/`, `.claude/commands/` and `.claude/agents/`. "The `permissions.additionalDirectories` setting in `settings.json` grants file access only and loads none of these" ([skills](https://code.claude.com/docs/en/skills#skills-from-additional-directories)). With `CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD=1`, an added folder's `CLAUDE.md` loads, but its `AGENTS.md` does not ([memory](https://code.claude.com/docs/en/memory#load-from-additional-directories)).
- Shared `.claude/settings.json` loads "from the current working directory's `.claude/` folder with no parent-directory fallback" ([permissions](https://code.claude.com/docs/en/permissions#working-directories)). So `home/.claude/settings.json` does not apply in a nested repo.

### Permissions

- [CC5] File reads need no approval "within the working directory and additional directories". File modification asks. `acceptEdits` "Automatically accepts file edits … for paths in the working directory or `additionalDirectories`" ([permissions](https://code.claude.com/docs/en/permissions#permission-system)). `--add-dir`, `/add-dir` and `additionalDirectories` extend the working directories ([permissions § Working directories](https://code.claude.com/docs/en/permissions#working-directories)).
- [CC7] Workspace trust "keys the trust on the git repository root, so the trust covers the whole repository apart from any git repository nested inside it, such as a submodule" ([permissions § workspace trust](https://code.claude.com/docs/en/permissions#project-allow-rules-and-workspace-trust)).

## 2. OpenAI Codex CLI

Source: `openai/codex` at `81b995a` (main, 2026-11-14). The installed CLI is 0.169.0 (tag `rust-v0.169.0`). I did not diff the tag against main, but the runs in [E3]–[E8] agree with the code.

- [CX1] [`core/src/agents_md.rs` L1–18](https://github.com/openai/codex/blob/81b995a6c9a4c978f399775cfa5ce50702368749/codex-rs/core/src/agents_md.rs#L1-L18): "Determine the project root by walking upwards from the current working directory until a configured `project_root_markers` entry is found … default marker list is used (`.git`) … Collect every `AGENTS.md` found from the project root down to the current working directory … We do **not** walk past the project root." [L199–233](https://github.com/openai/codex/blob/81b995a6c9a4c978f399775cfa5ce50702368749/codex-rs/core/src/agents_md.rs#L199-L233) builds the marker list from every config layer **except** `ConfigLayerSource::Project`, so a repo's `.codex/config.toml` cannot move the root. The default is in [`config/src/project_root_markers.rs` L5](https://github.com/openai/codex/blob/81b995a6c9a4c978f399775cfa5ce50702368749/codex-rs/config/src/project_root_markers.rs#L5) (`&[".git"]`). Docs: "Starting at the project root (typically the Git root), Codex walks down to your current working directory" ([AGENTS.md guide](https://learn.chatgpt.com/docs/agent-configuration/agents-md)). The config reference describes `project_root_markers` as a "List of project root marker filenames; used when searching parent directories for the project root" ([config reference](https://learn.chatgpt.com/docs/config-file/config-reference)).
- [CX2] [`agents_md.rs` L279–310](https://github.com/openai/codex/blob/81b995a6c9a4c978f399775cfa5ce50702368749/codex-rs/core/src/agents_md.rs#L279-L310): in each folder the candidates are `AGENTS.override.md`, `AGENTS.md`, then `project_doc_fallback_filenames`. Only the first that exists is used ([L262–273](https://github.com/openai/codex/blob/81b995a6c9a4c978f399775cfa5ce50702368749/codex-rs/core/src/agents_md.rs#L262-L273)).
- [CX3] [`ext/skills/src/host_roots.rs` L195–245](https://github.com/openai/codex/blob/81b995a6c9a4c978f399775cfa5ce50702368749/codex-rs/ext/skills/src/host_roots.rs#L195-L245): repo skills are `.agents/skills` in each folder from the project root to cwd. The root comes from the same non-Project layers ([L335–352](https://github.com/openai/codex/blob/81b995a6c9a4c978f399775cfa5ce50702368749/codex-rs/ext/skills/src/host_roots.rs#L335-L352)). Docs: "Codex scans `.agents/skills` in every directory from your current working directory up to the repository root" ([skills](https://learn.chatgpt.com/docs/build-skills)).
- [CX4] [`protocol/src/protocol.rs` L1449–1491](https://github.com/openai/codex/blob/81b995a6c9a4c978f399775cfa5ce50702368749/codex-rs/protocol/src/protocol.rs#L1449-L1491): the `WorkspaceWrite` writable roots are the configured `writable_roots`, plus "Always include defaults: cwd, /tmp (if present on Unix), and … TMPDIR". `codex exec --add-dir` and `sandbox_workspace_write.writable_roots` add roots. The sandboxing docs say: "Keep the project boundary as the default", and about the on-request policy: the agent "asks when it needs to go beyond that boundary" ([sandboxing](https://learn.chatgpt.com/docs/sandboxing)).
- [CX5] [`protocol/src/permissions.rs` L2382–2425](https://github.com/openai/codex/blob/81b995a6c9a4c978f399775cfa5ce50702368749/codex-rs/protocol/src/permissions.rs#L2382-L2425): only the **top-level** `.git` (folder or pointer file, and the gitdir it points to), `.agents` and `.codex` of each writable root are read-only. Nested repos' `.git` folders under a writable root stay writable.
- [CX6] The model prompt says: "The contents of the AGENTS.md file at the root of the repo and any directories from the CWD up to the root are included … When working in a subdirectory of CWD, or a directory outside the CWD, check for any AGENTS.md files that may be applicable" ([`core/gpt_5_2_prompt.md` L27](https://github.com/openai/codex/blob/81b995a6c9a4c978f399775cfa5ce50702368749/codex-rs/core/gpt_5_2_prompt.md?plain=1#L27)). This is an instruction to the model. No loader does it.
- [CX7] [`file-system/src/find_up.rs` L73–124](https://github.com/openai/codex/blob/81b995a6c9a4c978f399775cfa5ce50702368749/codex-rs/file-system/src/find_up.rs#L73-L124): a marker matches when `get_metadata` succeeds, whether `.git` is a folder or a file. So a submodule (`.git` file) and a gitignored clone (`.git` folder) both end the walk.

## 4. Cloud agents

- [CW1] "click the repository selector … and choose a repository for Claude to work in. You can add multiple repositories to work across them in one session" ([web quickstart](https://code.claude.com/docs/en/web-quickstart#start-a-task)). `claude --cloud` "works with a single repository at a time" and clones the GitHub remote, not the local checkout ([cloud](https://code.claude.com/docs/en/claude-code-on-the-web#start-a-cloud-session-from-your-terminal)).

The repo's `CLAUDE.md`, `.claude/rules/` and `.claude/skills/` carry over "Part of the clone". The layout under "above the clones" is documented only for self-hosted runners (`<repo-owner>-<repo>` folders). For Anthropic-hosted sessions it is **unverified**.

## 5. Test runs

Layout in `/tmp/claude-1000/nt/home` (a Git repo): `plugin-clone/` (own repo, gitignored), `sibling/` (own repo, gitignored) and `plugin-sub/` (submodule, `.git` is a pointer file). Each repo has an `AGENTS.md` with `MARKER_<REPO>_AGENTS`, a `CLAUDE.md` with `@AGENTS.md` and `MARKER_<REPO>_CLAUDE`, and the skills `<repo>-claude-skill` (in `.claude/skills`) and `<repo>-agents-skill` (in `.agents/skills`). Claude Code ran as `claude -p --model haiku`. Codex context came from `codex debug prompt-input`, which prints the model-visible input without a model, and the sandbox checks ran with `codex exec -m gpt-6-luna`. opencode ran as `opencode run --standalone -m openai/gpt-6-luna` with a clean `XDG_CONFIG_HOME`, because the user's plugin `@dietrichgebert/ponytail` stops opencode's location plugins from activating ("Location plugins did not finish activating"). The Claude and opencode context results are what the model reported. Codex context results are exact.

- [E1] Claude, cwd `plugin-clone` → markers `HOME_CLAUDE`, `CLONE_CLAUDE`, `CLONE_AGENTS`; skills `clone-claude-skill` only. Same pattern in `plugin-sub`. The home `@AGENTS.md` import was not loaded (external import, not approved in `-p`).
- [E2] Same layout with every `CLAUDE.md` deleted: Claude in `plugin-clone` → `HOME_AGENTS`, `CLONE_AGENTS`.
- [E3] Codex `prompt-input`: cwd `plugin-clone` → `MARKER_CLONE_AGENTS`, `clone-agents-skill`. `plugin-sub` and `sibling` give the same pattern. cwd `home` → `MARKER_HOME_AGENTS`, `home-agents-skill`, and no nested files.
- [E4] Codex with `-c 'project_root_markers=[".codex-home"]'` and `home/.codex-home` present: cwd `plugin-clone` → `MARKER_CLONE_AGENTS`, `MARKER_HOME_AGENTS`, `clone-agents-skill`, `home-agents-skill`. With `-c 'project_doc_fallback_filenames=["CLAUDE.md"]'`, no `CLAUDE` marker appears, because `AGENTS.md` wins in each folder.
- [E5] opencode, cwd `plugin-clone`, test dir outside `$HOME` → `CLONE_AGENTS` only. With `HOME=/tmp/claude-1000/nt` (so the test dir is under `$HOME`) → `CLONE_AGENTS`, `HOME_AGENTS`.
