# Template files merge the host and embedded Block trees like IntelliJ

A PHP file with inline HTML and a Twig file each get two parse trees from Neovim: one for the Host Language and one combined tree for the HTML. The two trees decide each other's indent. In `<div><?php if ($x): ?><span>` the `<?php if` is indented by the `<div>` and the `<span>` is indented by the `if`, but neither tree contains the other's structure. So before the engine runs, the Core merges the two Block trees into one. The merge is a port of IntelliJ's template merge (`TemplateFormatUtil.mergeBlocks` and `AbstractXmlTemplateFormattingModelBuilder`, Apache-2.0), because our output must match the Behaviour Records, and the operator chose to do what IntelliJ does. Markup is primary: an HTML Block is never split. At each HTML level, the host leaves directly between the HTML children span a range, and the topmost host Blocks inside that range join the level. A Block that contains Blocks of the other tree takes them in as children. A host Block that crosses an HTML Block is split into its children. One set of indent Options (indent, continuation indent, tabs) applies to the whole file, and the Host Language's Language Plugin chooses it. A PHP file with inline HTML uses HTML's indent Options for all of its lines. A Twig file uses Twig's. This follows the Behaviour Records. The merge prototype ([`prototype/merge`](https://github.com/a1exk-dev/codestyle.nvim/tree/prototype/merge/prototype/merge), "How does the Core merge host and embedded-language block trees?", #19) matches PhpStorm's indentation in 65 of 68 golden cases. The other 3 are not about the merge.

## Considered Options

- **Keep the trees separate**, so that each language formats only its own lines. Rejected: the HTML pass cannot see the PHP `if`, and the PHP pass cannot see the `<div>`. Twig files would get almost no formatting, because the Twig grammar does not even nest `{% if %} … {% endif %}`.
- **A plain containment merge**, where the Block that contains the other one is the parent. It is simpler, but it differs from PhpStorm when PHP code comes before top-level HTML. PhpStorm indents that HTML one level (`r2_php_first_then_html.php`).
- **The indent Options of each Block's own language.** This differs from PhpStorm on every PHP file with inline HTML.

## Consequences

- This refines ADR-0002. The embedded part follows its own Language Plugin's rules with its own language's Code Style, except for the indent Options, which the Host Language chooses for the whole file.
- A Language Plugin's Block builder does not map one node to one Block. It leaves holes for the embedded code (PHP `text`, Twig `content`). It splices glue nodes into their parent (PHP `text_interpolation` and `colon_block` cross HTML elements). It also adds synthetic Blocks: a PHP `<?php … ?>` region for "Indent code in PHP tags", and Twig tag pairs, because the Twig grammar is flat. Leaf ranges are trimmed of whitespace, because some grammars include it.
- A parent's indent and Spacing rules also get children of the other language. The lowest Block that holds both leaves of a Gap owns that Gap. For example, a Twig `{% block %}` owns the Gaps between the HTML words inside it.
- A host Block that crosses HTML loses its structure in that place. HTML that IntelliJ reports as broken keeps its text, as an `ERROR` node does (ADR-0002). An example is an element without its end tag, which tree-sitter-html accepts without an error. The HTML Language Plugin must detect such elements itself.
- This decision covers only template files, where the embedded code is one combined injection. It does not decide `<script>` and `<style>` in HTML, Vue, or Blade.
